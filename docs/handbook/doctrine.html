Doctrine

Constitution

The wrapper does one job: keep MCP stdio servers cheap and controllable while preserving raw JSON-RPC behavior for backend-owned dynamic work.

The controlling rule is: cache static discovery, proxy backend-owned dynamics, expose wrapper lifecycle through mcp.wrapper, and prove state transitions by owner readback. The wrapper must not become an MCP SDK, rule engine, or semantic owner of backend behavior.

First Principles

  • JSON-RPC line protocol is the transport boundary.
  • MCP initialize and list results are stable enough to cache after backend handshake.
  • src/tools owns the wrapper tool schema and dispatch surface; CLI and MCP are projections over that owner.
  • mcp.wrapper is the reserved wrapper-owned MCP tool. Other tool calls, resource reads, prompts, completions, logging, subscriptions, and unknown future methods belong to the backend.
  • Backend subprocesses are external resources and must be isolated in process groups.
  • Daemon sharing is legal only when a single backend is correct for the server's state model.

Rejected Drift

Do not justify new layers with generic proxy patterns. A new owner is legal only when this handbook, the route table, and proof gates name the boundary.
