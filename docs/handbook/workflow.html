Workflow

Change Route

  1. Read CLAUDE.md for act rules and release gates.
  2. Use this handbook to locate the owning chapter and boundary.
  3. If behavior changes, update handbook truth before code.
  4. Update the owning manager or interface surgically; do not create a second control plane.
  5. Run the proof route named by the gate before claiming completion.

Release Route

Build release binaries from the development master worktree with cargo build --release, verify CLI flags, run real-server smoke tests, check orphan processes, bump Cargo version, update changelog, and keep release projection decisions explicit. The release worktree is a public artifact target, never the source used to develop or compile a fix.
