Workflow

Change Route

  1. Use local act rules for release gates; they are not part of the public release surface.
  2. Use this handbook to locate the owning chapter and boundary.
  3. If behavior changes, update handbook truth before code.
  4. Update the owning manager or interface surgically; do not create a second control plane.
  5. Run the proof route named by the gate before claiming completion.

Release Route

Build release binaries with cargo build --release, verify CLI flags, run real-server smoke tests, check orphan processes, bump Cargo version, update changelog, and keep release branch decisions explicit.
