Legal Shapes

The executable contract is JSON-RPC 2.0 over line-delimited stdio plus MCP method envelopes. The repository does not currently have a root schema.json; proof uses tests/fixtures/mcp-schema.json and the conformance validator.

Rule

New protocol shape support starts with route ownership and conformance proof. Hook responses must be local wrapper JSON-RPC results with stable fields for backend generation, cache epoch, state, and readback evidence. Wrapper tool shapes start in src/tools; CLI argv parsing and MCP tools/call parsing are projections of that schema, not independent schema owners.

Daemon request identity is the composite (session_id, raw_client_id); a raw JSON-RPC id is unique only inside its session and cannot be used as a cross-session lookup or cancellation fallback. This is an internal ownership key and does not change the MCP wire schema.

N:1 runtime state is represented as owner rows plus indexes, not counters or a current-session pointer. The Request row is the active-call truth. Backend-id and progress-token maps are secondary indexes into that row and must be removed in the same terminal transition. PeerRequest identity is also session-complete; equal peer IDs and progress tokens may coexist in different sessions.
