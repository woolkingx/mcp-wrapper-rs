Flow

State Movement

Startup builds cache by spawning a temporary backend, performing initialize, sending initialized, querying supported list methods, then killing the temporary backend in normal mode. Daemon mode keeps the initialized backend alive and broker-owned.

Pass-through calls generate backend IDs, restore client IDs on response, and keep the backend alive until idle reaper or shutdown. Normal mode and broker mode keep pass-through calls serialized, but the client read loop stays active while a backend call is in flight.

mcp.wrapper calls are not pass-through calls. Runtime or broker code recognizes tools/call for the reserved tool name, builds the current tools context, and calls tools::invoke. tools validates the action and params, then calls the existing backend/cache owner APIs through object methods and returns a unified readback envelope.

Server-to-client backend requests are request-scoped. A backend peer request is relayed to the active client, the client's JSON-RPC response is written back to the backend, and the backend's final response returns to the original client request ID. Broker mode rejects unassociated backend requests instead of broadcasting them.

Backend intelligence follows a hook/observe chain: typed backend event, backend generation state, explicit wrapper hook, discovery cache refresh by generation, then notification or status evidence after readback. Backend stdout events are classified as notifications, peer requests, unmatched responses, or process exits before runtime or broker code acts on them.
